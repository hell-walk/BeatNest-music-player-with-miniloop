# Launch checklist – implementation map

Each item from the checklist, where it lives, and how to verify it.

| # | Item | Where | How to verify |
| --- | --- | --- | --- |
| 1 | **Privacy policy** | `client/src/pages/PrivacyPage.jsx` at `/privacy`. Describes exactly what the app stores (account fields, Mini Loop, session, first-party analytics), every cookie/storage key, retention periods, rights, children, security. Linked from footer, signup form and cookie banner. | Open `/privacy`. Replace the placeholder contact email before launch and have counsel review. |
| 2 | **Terms & conditions** | `client/src/pages/TermsPage.jsx` at `/terms`. Signup requires `acceptTerms` (validated client + server). | Open `/terms`; try signing up without ticking the box. |
| 3 | **Remove frontend secrets** | Client has no env secrets (`client/.env.example`); runtime config comes from `GET /api/config` (non-secret only). Server secrets live in `server/.env` (git-ignored). The ColorThief CDN script was replaced by `hooks/useDominantColor.js`. `scripts/check-secrets.mjs` scans client code + bundle for key patterns and checks `.env` is ignored. | `npm run check:secrets` |
| 4 | **Enforce HTTPS** | `server/src/middleware/security.js`: 301 redirect http→https (POST → 403), HSTS 180 days + preload, `upgrade-insecure-requests` in CSP, `secure` cookies. Controlled by `ENFORCE_HTTPS` / `TRUST_PROXY`. | Set `ENFORCE_HTTPS=true TRUST_PROXY=1`, request with `X-Forwarded-Proto: http` → 301. |
| 5 | **Cookie consent banner** | `components/consent/CookieConsent.jsx` + `context/ConsentContext.jsx`. Equal-weight Accept / Essential-only buttons, decision in `localStorage`, reopen via footer "Cookie settings". Analytics never loads before acceptance (`lib/analytics.js`). | Load the site fresh; check Network tab – no analytics calls until Accept. |
| 6 | **Meta titles/descriptions** | Per-route titles/descriptions in `shared/src/routes.js`; server injects them into `index.html` per URL (`server/src/app.js renderIndexHtml`); client updates them on navigation (`hooks/useSeo.js`). Playlist pages get playlist-specific meta. | `curl -s localhost:3000/privacy | grep -i '<title>'`; server test `spa.test.js`. |
| 7 | **Social preview image** | `client/public/og-image.png` (1200×630) generated by `scripts/generate-icons.mjs`; `og:*` and `twitter:*` tags in `index.html`, rewritten per route; playlist pages use their cover. | Paste a URL into a link-preview debugger after deploy. |
| 8 | **Favicon** | `favicon.svg` (vector), `favicon.ico` (16/32/48), `apple-touch-icon.png`, `icon-192/512.png`, `site.webmanifest` – all generated from `assets-src/logo.png` by `scripts/generate-icons.mjs`. Replaces the 1.8 MB base64 "SVG". | Check the browser tab / add-to-home-screen. |
| 9 | **Sitemap and robots.txt** | `scripts/generate-sitemap.mjs` → `client/public/sitemap.xml` (static pages + every playlist) and `robots.txt` (disallows `/api/`, `/login`, `/signup`). Run with `SITE_URL=https://…`. | `curl localhost:3000/sitemap.xml` |
| 10 | **Image alt text** | Every `<img>` has `alt` (cover alt text comes from the API: "<Title> playlist cover art"). Icons are inline SVG with `aria-hidden`; icon buttons have `aria-label`s. | Inspect any card; run a Lighthouse accessibility audit. |
| 11 | **Image compression** | `scripts/optimize-images.mjs`: covers → 200/400 px WebP + JPEG fallback (`<picture>` + `srcset`), backgrounds → WebP (259 KB → 73 KB, 263 KB → 66 KB), lazy-loaded covers. | `npm run assets` prints a before/after table. |
| 12 | **Page load speed check** | `scripts/perf-check.mjs` measures TTFB, HTML/JS/CSS bytes on the wire (brotli/gzip via `compression`), LCP image and request count against budgets; hashed assets cached `immutable` 1 year; routes code-split with `React.lazy`. Result: 16 ms TTFB, 119 KB JS, 6 KB CSS, 21 KB LCP image. | `npm run check:perf` (server running) or `npx lighthouse http://localhost:3000 --view`. |
| 13 | **Color contrast fixes** | Token palette in `client/src/styles/tokens.css`; `scripts/check-contrast.mjs` verifies 19 text/UI pairs against WCAG AA. Fixed v1's 2.3:1 active-track colour and an invisible focus ring on the primary button (now a gold ring with a dark gap). | `npm run check:contrast` |
| 14 | **Mobile responsiveness** | Fluid grid (`pages.css`, `library.css`, `PlayBar.css`): sidebar stacks below 1024 px, play bar reflows to two rows, volume hidden below 640 px (hardware keys), 44 px tap targets, `safe-area-inset` padding, play buttons always visible on touch devices. | Resize or use device emulation at 375/768/1280 px. |
| 15 | **Custom 404 page** | `pages/NotFoundPage.jsx` (`noindex`), and the server returns a **real 404 status** for unknown URLs and unknown playlist slugs while still serving the app (`server/src/app.js`). API unknown routes → JSON 404. | `curl -o /dev/null -w '%{http_code}' localhost:3000/nope` → 404 |
| 16 | **Broken link fixes** | v1's Spotify legal links, absolute `/images/...` paths and the unused `images.jpg` were replaced. `scripts/check-links.mjs` verifies every page, sitemap entry, asset, cover variant and audio file (117 checks) and that bad URLs 404. | `npm run check:links` |
| 17 | **Form validation** | One zod schema per form in `shared/src/validation/` used by `hooks/useForm.js` (validate on blur, on submit, focus first error, `aria-invalid`/`aria-describedby`, `role="alert"`) and by `server/src/middleware/validate.js` (same schema, returns `{ errors: { field } }`). | Submit the signup form empty; try a 2-year-old DOB. |
| 18 | **Spam protection** | `server/src/middleware/antiSpam.js`: hidden honeypot field, server-signed form token with minimum fill time (1.5 s) and 24 h expiry; `rateLimit.js`: 20 login attempts / 15 min, 10 signups / h, 120 analytics events / min, 600 API req / 15 min. | Server tests `auth.test.js` (honeypot, missing token). |
| 19 | **Analytics setup** | `client/src/lib/analytics.js` (consent-gated façade) + `server/src/services/analytics.service.js` (first-party store, 90-day prune) + `npm run report -w server`. Switch to Plausible/GA4 with `ANALYTICS_PROVIDER`; CSP updates automatically. Events: `page_view`, `play_playlist`, `play_track`, `mini_loop_saved`, `cta_start_listening`, `signup_completed`, `login`. | Accept analytics, browse, then `npm run report -w server`. |
| 20 | **Single clear CTA** | One filled primary button per screen: **Start listening** on the home hero; **Play all** on a playlist; **Create account** / **Log in** on auth pages; **Back to the player** on 404. Header links are ghost/secondary. `Button` component documents the rule. | Visual check of each page. |

## Still manual before launch

- Real domain in `SITE_URL` (also when generating the sitemap) and a strong `SESSION_SECRET`.
- Replace `*@beatnest.example.com` contact addresses in the Privacy and Terms pages; legal review.
- Confirm you hold the rights to stream the bundled recordings.
